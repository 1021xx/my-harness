# R5 게이트

## 게이트 정의

| 게이트 | 통과 조건 | 실패 시 복귀 |
|---|---|---|
| G1 입력 게이트 | 대상 파일 1개 이상, 변경 요청 1개 이상, 표준 예시 1개 이상 | 1단계 대상·기준 확인 |
| G2 매핑 게이트 | 모든 차이 항목에 기존 구조 1개 이상, 실제 사용 근거 1개 이상 | 2단계 구조 비교 |
| H1 사람 승인 게이트 | 매핑표 완성 후 코드 수정 전 승인 기록 1개, 승인 전 대상 프로젝트 수정 파일 0개 | 거절 시 3단계 기존 구조 매핑 |
| G3 신규 클래스 게이트 | 기존 프로젝트에 없던 class 토큰 0개, 신규 CSS 클래스 선택자 0개 | 3단계 기존 구조 매핑 |
| G4 검증 게이트 | 필수 검사 `FAIL` 0개, 사유 없는 필수 `미확인` 0개 | 4단계 최소 수정 |

`H1`은 실행당 유일한 사람 승인 지점이다.

## 승인 기록

`runs/<작업ID>/status.json`에 다음 구조로 기록한다.

```json
{
  "approval": {
    "approved": true,
    "approved_at": "ISO-8601 날짜·시간",
    "approved_scope": "03-component-map.md",
    "scope_hash": "매핑표 파일의 SHA-256"
  }
}
```

## 기계 판정 규칙

- `approved`가 `true`가 아니면 코드 수정을 금지한다.
- `approved_scope`가 `03-component-map.md`가 아니면 실패한다.
- 현재 매핑표의 SHA-256이 `scope_hash`와 다르면 승인을 무효화하고 H1으로 복귀한다.
- 승인 전 대상 프로젝트의 변경 파일 수가 1개 이상이면 실패한다.
- 승인 기록은 실행당 정확히 1개만 허용한다.
- G3는 수정 전 프로젝트 전체의 HTML/JSP/JS/CSS 클래스 목록과 수정 후 추가 토큰을 비교해 판정한다.
