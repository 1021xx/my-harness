# R3 파이프라인

## 단계별 흐름

| 단계 | 작업 | 입력 | 출력 | 실패 시 복귀 |
|---|---|---|---|---|
| 1. 대상·기준 확인 | 대상 화면과 변경 요청을 확인하고 `UiStandardRenewal.jsp`의 관련 예시를 찾는다. | 대상 화면·관련 파일·변경 요청·`UiStandardRenewal.jsp` | 대상 범위와 적용할 표준 예시 목록 | 입력이 없으면 1단계에서 중단 |
| 2. 구조 비교 | 대상 화면을 표준 예시 및 실제로 잘 구현된 동종 페이지와 비교한다. | 대상 코드·표준 예시·동종 정상 페이지 | 임의 구조, 미사용 공통 컴포넌트, 상태·동작 차이 목록 | 비교 근거가 부족하면 1단계로 복귀 |
| 3. 기존 구조 매핑 | 발견된 차이를 기존 DOM·클래스·공통 컴포넌트에 연결한다. | 차이 목록·기존 클래스 사용처·공통 CSS/JS | `현재 구조 → 사용할 기존 구조` 매핑표 | 대응 구조가 없으면 사용처를 다시 조사하고, 그래도 없으면 사용자 승인 전까지 중단 |
| 4. 최소 수정 | 매핑표에 따라 임의 구조를 기존 구조와 공통 컴포넌트 사용 방식으로 수정한다. | 승인 가능한 매핑표·대상 코드 | 수정된 화면 코드 | 신규 클래스가 생기거나 요청 범위를 벗어나면 3단계로 복귀 |
| 5. 검증·기록 | 표준 예시와 정상 페이지를 다시 대조하고 정적 검사와 브라우저 회귀 검사를 수행한다. | 수정 코드·표준 예시·정상 페이지·검사 기준 | 항목별 `PASS/FAIL/미확인/해당 없음` 결과 | `FAIL`이면 4단계, 필수 `미확인`이면 검증 환경 확보 후 5단계로 복귀 |

## 측정 조건

| 조건 | 허용값 |
|---|---:|
| 새로 추가된 클래스 | 0개 |
| 표준 구조로 매핑되지 않은 임의 구조 | 0개 |
| 적용 가능한 필수 검사의 `FAIL` | 0개 |
| 사유 없는 필수 `미확인` | 0개 |
| 각 구조 변경에 연결된 표준 예시 또는 정상 페이지 근거 | 1개 이상 |

## 정상 페이지 참고 순서

1. `UiStandardRenewal.jsp`
2. `reference.md`에 기록된 정상 후보
3. 대상과 같은 유형의 실제 업무 화면
