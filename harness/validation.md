# R8 검증과 리뷰

## 자동 테스트

| 검증 항목 | 실행 방법 | 기대 결과 |
|---|---|---|
| 필수 입력 누락 | 대상 파일·변경 요청·표준 예시 중 하나를 0개로 설정 | G1 `FAIL` |
| 매핑 근거 누락 | 차이 항목에서 기존 구조 또는 사용 근거 제거 | G2 `FAIL` |
| 승인 전 코드 변경 | H1 승인 없이 대상 프로젝트 파일 변경 | H1 `FAIL` |
| 신규 클래스 추가 | 기존 목록에 없는 class 토큰 또는 CSS 선택자 추가 | G3 `FAIL` |
| 검증 실패 | 필수 항목에 `FAIL` 또는 사유 없는 `미확인` 기록 | G4 `FAIL` |
| 정상 실행 | 모든 필수 입력·매핑·승인·검증 조건 충족 | 전체 `PASS` |

각 테스트는 1회 이상 실행한다.

## 판정 스크립트

### `scripts/validate-run.ps1`

- G1, G2, H1, G4를 검사한다.
- 단계 파일과 `status.json`을 검사한다.

### `scripts/check-new-classes.ps1`

- 수정 전 프로젝트의 클래스 목록을 수집한다.
- 수정 후 추가된 class 토큰과 CSS 클래스 선택자를 비교한다.
- 기존 목록에 없는 클래스가 1개 이상이면 G3를 실패 처리한다.

## 외부 프로젝트 통합 검증

- 하네스 제작 단계에서는 외부 프로젝트를 읽기 전용으로 확인한다.
- 실제 수정 통합 테스트는 사용자가 구체적인 대상 화면을 지정한 첫 실행에서 수행한다.
